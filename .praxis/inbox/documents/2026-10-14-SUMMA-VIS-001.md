## Confirmed issue
`app/summa-app.css` contains `var(--ef-color-action-primary, #0b5cad)`, `var(--ef-color-text-link, #0b5cad)`, `var(--ef-color-focus, #1f6feb)` and `var(--ef-color-text-danger, #b42318)`. Those four names are not supported in the pinned Forma 0.6.1 public core token contract, so the explicit fallback colors determine the rendering instead. The first accounting-app implementation introduced these references in [commit a834783](https://github.com/kemiller2002/summa/commit/a8347836a5d881be84d48dc7f251b7ae0a4420d1).

Illustrative WCAG 2 contrast calculations from source colors: fallback blue `#0b5cad` on Forma dark carbon `#171a18` is ~2.63:1; red `#b42318` on that carbon is ~2.67:1. These are **potential** text failures for those pairings, not proof a particular screen currently displays them.

## Requirements
- **SUMMA-VIS-001.1:** Remove every unresolved/rebranded Forma color reference and arbitrary color fallback; use an existing approved semantic role or request a deliberate new public role through Forma rather than inventing aliases.
- **SUMMA-VIS-001.2:** Record Summa's explicit product palette, light/dark policies, and task-oriented hierarchy (financial totals, overdue/blocked work, draft vs posted/issued, review, actionable vs informational status, header/navigation, focus and chart/table uses). Approved visual intent belongs in the governed Ordo decision path once available.
- **SUMMA-VIS-001.3:** Check colors and non-color signals for accounting-critical states: unpaid/overdue, blocked issue, successful payment, failed save, unknown/pending state, selected navigation, validation/focus, and print-versus-screen output.
- **SUMMA-VIS-001.4:** Capture rendered and computed-color evidence on representative screens/states in light/dark, mobile/desktop, 200% zoom, keyboard focus, forced colors and grayscale/CVD screening. Contrast pass does not equal design approval.
- **SUMMA-VIS-001.5:** Add failing regression tests for each original unsupported token and for intentionally wrong-theme pairings; integrate the shared Forma/Dokimos checker and Praxis receipt gate when published. Retain independent checks locally in the interim.
- **SUMMA-VIS-001.6:** Avoid forking or duplicating Forma CSS; do not change accounting semantics or state to compensate for visual defects.
